# Skill: Spec (TDD & Interface Detailer)

## Purpose
Read the core architecture blueprint (`docs/specs/[feature]_core.md`) and detail it into a complete, machine-readable TDD blueprint (`docs/specs/[feature].md`) so the `implement` executor can build it mechanically.

## Execution Rules

### 1. Pre-process (Scan & Context Alignment)
- **Decisions Context**: Start by loading `docs/decisions/decisions.md` (the cumulative sliding window decisions log) to align with recent architectural decisions and prevent drift.
- **Load Core Specification**: Read `docs/specs/[feature]_core.md` generated by the `arc` skill.

### 2. Contract & Test Matrix Formulation
- **Data Shapes & Types**: Translate the abstract core data shapes defined in `_core.md` into exact Python 3.11 type hints, Pydantic Models, or TypedDicts.
- **Contract Changes**: Define exact class and function signatures (with full type hints) and return types.
- **TDD Test Scenario Matrix**:
  - Design concrete test cases (Happy Path, Edge Cases, Error Handling) matching the core logic boundaries.
  - **Constraint Alignment (CRITICAL)**: Explicitly verify and map every constraint and edge case listed in `[feature]_core.md` to a corresponding test scenario in Scenario 2 (Edge Cases) or Scenario 3 (Error Handling). Do not omit any constraint.
  - Provide a concrete **Raw Python Code** snippet for mocking complex objects/APIs so the executor can copy-paste and verify immediately.

## Output Format
Create a markdown file at `docs/specs/[feature].md`:

- **# 🎯 Objective**: 1-sentence goal.
- **# 📦 Context & Dependencies**: Exact import statements and data models.
- **# ✍️ Contract Changes**: EXACT class and function signatures with type hints.
- **# 🧪 TDD Test Scenario Matrix (CRITICAL)**:
  - Scenario 1 (Happy Path - Test Setup)
  - Scenario 2 (Edge Cases - Validation/Bounds)
  - Scenario 3 (Error Handling - Exceptions)
  - Mock Boilerplate Snippet
- **# 🛠️ Algorithmic Plan**:
  - Target Location, Anchor code, and step-by-step logic flow.
