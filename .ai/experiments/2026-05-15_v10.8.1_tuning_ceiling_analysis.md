## Critical Finding: HMM Init Stability

During 레버 B testing, discovered HMM collapse mechanism:
1. `_train_hmm` first 500-bar window converges to CHOP-dominant posterior
2. Subsequent windows inherit CHOP parameters as init
3. `semantic_prior` has **zero penalty for CHOP** → collapse cascade
4. `sticky_labels` cannot recover from collapsed posterior

**Fix**: Add CHOP constraint to semantic_prior or implement multi-start init.

## Architecture Ceiling Analysis

### Damp Tail-Capture: 71.5% Ceiling

**Decomposition**:
```
Damp T/C = Policy soft_gate_coverage + Policy hard_gate_coverage + Policy near_flat_coverage
         ≤ min(Regime T/C + boost_margin, policy_saturation_point)
         = min(22.3% + ~50%p, 71.5%)
         → Currently saturated
```

**Why further improvement blocked**:
- Regime T/C is 22.3% (upstream limit)
- Policy boost can add ~50%p when gates fully open → 72% theoretical max
- Further gate opening raises Protected Exposure > 50% → violates `g-hmm.md` constraint (30~50%)
- Supervised score SupHit ~19% is lagging-indicator ceiling (features are all concurrent/lagging)

**Path to 85%**:
1. **Option A**: Raise Regime T/C from 22.3% to 40%+ (requires HMM restructuring)
2. **Option B**: Raise SupHit from 19% to 35%+ (requires micro-signals)
3. **Option C**: Both at moderate level (Regime T/C 30%, SupHit 28%)

### Avg-Duration: 20 Bars Ceiling

**Decomposition**:
```
Avg-Duration = apply_sticky_labels(hard_states, sticky_min_duration)
             where hard_states = argmax(HMM posterior per bar)
             
Raw hard_state duration ≈ 2.7 bars (1104 switches / 3000 bars)
sticky_min_duration=[48,32,28,16,20] mitigates but cannot overcome
```

**Why further improvement blocked**:
- HMM posterior is multi-modal in CHOP region (states have similar prob per bar)
- Sticky labels replace short runs with prior state, but only enforce min duration
- Even with aggressive sticky_min_duration=[132,56,42,16,20], collapse risk increases

**Path to 24 bars**:
1. **Option A**: Stronger HMM priors to force binary BULL/BEAR discrimination (less CHOP overlap)
2. **Option B**: Semantic prior to sharpen state separation (currently only BULL/BEAR constrained)
3. **Option C**: Multi-objective loss (NLL + state-separation penalty)

## Lessons Learned

1. **Lagging-Indicator Ceiling**: Supervised tail score built on concurrent/lagging features cannot exceed ~19% hit rate. Micro-signal augmentation is necessary.
2. **Policy Saturation**: Execution policy is already at threshold limits set by `g-hmm.md` constraints. No config-only tuning can move metrics significantly.
3. **HMM Collapse Risk**: Skewed-t init stability is fragile. CHOP state semantic_prior absence creates zero-cost sink. Multi-start init recommended for robustness.
4. **Architecture Coupling**: Each metric (Tail-Capture, Avg-Duration, Crisis-Prec, Protected Exposure) is coupled through the same HMM posterior. Moving one metric in isolation is infeasible.
