# HMM 리스크 오버레이 모듈 목표 및 평가 기준 (H-HMM)

이 문서는 HMM 모듈이 "방향 예측기"가 아닌 "리스크 예산 조절기"로서의 역할을 완벽히 수행하기 위해 달성해야 할 정량적 목표를 정의한다. 모든 AI 개선 작업은 본 지표를 최적화하는 방향으로 진행되어야 한다.

## 1. 핵심 철학 (v11.0.0 기준: Preventive Risk-Off)
- **보험으로서의 CRISIS**: 위기는 발생 후가 아니라 **발생 전(과열 구간)**에 감지되어야 한다.
- **예방적 방어**: Skewed-t 분포를 활용하여 하방 왜도가 관측되는 즉시 레버리지를 회수한다.
- **구조적 안정성**: 잦은 체제 전환은 거래 비용을 증가시키므로, 구조적 변화가 확인될 때만 전환한다.
- **방향 중립 (Direction Neutral)**: HMM은 **리스크 예산 조절기**이며 방향 예측기가 아니다. Regime별 신호 가중치(`BETA_REGIME_*`)는 **반드시 ≥ 0**이어야 한다. 음수는 국면별 신호 반전을 의미하며, 이는 과적합 경로이자 본 모듈 철학의 근본 위반이다.

## 2. 정량적 평가 지표 및 합격 기준 (Pass/Fail)

### A. 추론 레벨 (Inference Level: HMM 자체 성능)
| 평가 지표 | 합격 기준 (Pass) | 실무적 의미 |
| :--- | :--- | :--- |
| **Lead-Lag Tail Capture** | **> 40.0%** | CRISIS 감지 후 8개봉(32h) 내 실제 Tail Event 발생 확률 (예측력). |
| **Avg-Duration** | **> 18 bars** | 4h 기준 체제 유지 기간 평균 3일 이상. 불필요한 스위칭 비용 억제. |
| **Crisis-Prec** | **> 10.0%** | 위기 신호의 정밀도. 보험 오버레이는 낮은 정밀도/높은 재현율이 의도된 트레이드오프. |
| **Vol-Scale (Calm)** | **< 0.85x** | '안전' 상태는 시장 평균보다 15% 이상 낮은 변동성을 유지해야 함. |

### B. 정책 레벨 (Policy Level: 최종 실행 성능)
| 평가 지표 | 합격 기준 (Pass) | 실무적 의미 |
| :--- | :--- | :--- |
| **Damp Tail-Capture** | **> 80.0%** | Hazard Overlay 결합 후 하위 5% 급락장의 80% 이상 노출 방어. |
| **Damp Crisis-Cap** | **> 90.0%** | 위기 구간에서의 실질적인 자산 노출 방어율 (실행 레벨). |
| **Protected Exp.** | **30% ~ 55%** | 전체 운용 기간 중 방어 로직이 활성화된 비율 (효율적 리스크 관리). |
| **False-Flat** | **< 15.0%** | 위기로 오판하여 놓친 수익 기회비용 상한. |

## 3. Regime β 파라미터 제약 (최적화 공간 하드 제약)
최적화 파이프라인에서 `BETA_REGIME_*` 파라미터는 다음 범위를 반드시 준수한다. **음수 허용은 HMM을 directional timing 입력으로 전용하는 철학 위반이자 단일 윈도우 과적합 경로**이므로 엄격히 금지한다.

| 파라미터 | 허용 범위 | 근거 |
| :--- | :--- | :--- |
| `BETA_REGIME_BULL` | `[0.0, 2.0]` | 양수만 허용 (BULL=1.0 기준점) |
| `BETA_REGIME_BEAR` | **`[0.0, 1.5]`** | **음수 금지**. 음수 = 신호 반전 = directional timing 전용 = 철학 위반 |
| `BETA_REGIME_CHOP` | `[0.0, 1.0]` | 감쇠만 허용 (1.0 = 신호 유지, 0.0 = 차단) |
| `BETA_REGIME_CRISIS` | `0.0` 고정 | 신호 완전 차단. CRISIS 알파 신뢰도 붕괴 |

## 4. 로그 출력 및 감사 가이드라인
- 모든 HMM 진단 로그는 위 지표를 기반으로 `[PASS]`, `[FAIL]`, `[READY]` 상태를 명시한다.
- **Audit v20** 부터는 `Lead-Lag Tail Capture`를 HMM 성능 평가의 최우선 순위로 둔다.
- 단순 수익률(`G`)보다 `Risk Isolation` (BEAR 상태에서의 낮은 수익률 및 변동성 제어) 능력을 우선한다.
- **최적화 진입 전제**: 본 문서의 모든 게이트를 통과한 HMM artifact만 Optuna 최적화 입력으로 허용한다.
